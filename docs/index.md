casmsocial is a Python framework for implementing agent-based models that simulate the dynamics of a synthetic population

## Input Tables

Runtime YAML configs identify DuckLake source tables with `places.table`,
`households.table`, `persons.table`, `activities.table`, and `contacts.table`.
`Place` agents represent physical locations. `Household` agents represent social
household units loaded from `households.table`, often named `hh` in input
schemas; each household links to a physical `Place` and to its member `Person`
agents.

If a household row does not include `place_id`, casmsocial uses `sp_id` as the
household's physical place id. When `households.table` is configured, a person's
`sp_hh_id` is resolved through the household first, then to the linked physical
place for rank ownership and place projection setup.

## Road Networks

The project includes an initial scaffold for OpenStreetMap road-network integration.

Enable it with the `roads.*` configuration keys:

```yaml
roads.enabled: false
roads.nodes.file: ''
roads.edges.file: ''
roads.place_snap.file: ''
roads.mode: 'drive'
roads.time_model: 'validated_gap'
```

The runtime expects three artifacts:

- road nodes
- road edges
- place-to-road-node snaps

These artifacts can be generated by `scripts/build_road_network.py` from an OSM XML extract and a Parquet place table:

```bash
uv run python scripts/build_road_network.py \
  --osm-file data/roads.osm \
  --places-file data/places.parquet \
  --nodes-out data/road_nodes.parquet \
  --edges-out data/road_edges.parquet \
  --snaps-out data/place_road_snap.parquet \
  --report-out data/road_artifacts.json
```

The MVP builder supports drive-mode road filtering, simple travel-time estimates from `maxspeed` or road-class defaults, nearest-node snapping, and Parquet output compatible with the `roads.*.file` settings.
Its optional JSON report captures build inputs, artifact paths, row counts,
road-type counts, snap coverage, and aggregate length and travel-time totals.

The local smoke suite exercises that path with `make mvp-built-roads`, using
the source fixtures in `examples/mvp/roads.osm` and
`examples/mvp/road_builder_places.csv`.

## Behavior Logging

The project includes a lightweight behavior-state observer for the local `LLMBehaviorEngine`.

Enable it with:

```yaml
observers.output_dir: 'data/output'
observers.behavior_log.enabled: true
observers.behavior_log_file: 'behavior_log.parquet'
```

All observer outputs use `observers.output_dir`; observer file settings must be
filenames only. Output datasets are Hive-partitioned by `run_id`, `tick`, and
`rank`. The run id defaults to `seed_<random.seed>` when `simulation.run_id` is
omitted, and `random_seed` is stored as row metadata.

The output includes per-agent, per-tick fields for:

- `run_id`
- `random_seed`
- `last_decision`
- `last_llm_summary`
- `last_memory_event_type`
- `last_plan_adjustment_requested_kind`
- `last_plan_adjustment_applied`
- `last_plan_adjustment_skip_reason`
- `last_plan_adjustment_kind`
- `last_plan_adjustment_delay_minutes`
- `last_plan_adjustment_target_activity_id`
- `last_plan_adjustment_target_place_id`
- `safety_signal`
- `social_signal`
- `obligation_signal`
- `schedule_signal`
- `reply_signal`

This log is intended for scenario inspection and calibration of behavior-engine dynamics without reading debug traces.

For changed-only state output, enable:

```yaml
observers.delta_agent_state.enabled: true
observers.delta_agent_state_file: 'agent_state_delta.parquet'
observers.delta_agent_state_audit_file: 'agent_state_delta_audit.parquet'
```

`DeltaAgentStateLogger` emits a full state row only when an agent's normalized
state changes on the local rank. Each row includes `run_id`, `random_seed`,
`state_hash`, and `change_mask`. The audit output records `agents_evaluated`
and `agents_changed` for every run, rank, and tick.

Reconstruct dense state rows from the changed-only output with:

```bash
uv run python scripts/reconstruct_agent_state.py \
  --delta-log output/agent_state_delta.parquet \
  --audit-log output/agent_state_delta_audit.parquet \
  --output output/agent_state_reconstructed.parquet \
  --overwrite
```

The reconstructed table is partitioned by `run_id`, `tick`, and `rank` and
includes `source_tick`, which identifies when each agent's carried-forward state
last changed.

Adjustment field meanings:

- `last_plan_adjustment_requested_kind`: the adjustment requested by the behavior engine
- `last_plan_adjustment_applied`: whether the request changed the plan
- `last_plan_adjustment_skip_reason`: why a request was skipped, such as `no_slack`, `no_future_activity`, or `no_eligible_future_activity`
- `last_plan_adjustment_kind`: the adjustment that was actually applied, or empty when skipped
- `last_plan_adjustment_delay_minutes`: applied delay for `defer_next_activity`
- `last_plan_adjustment_target_activity_id`: activity id targeted by the request
- `last_plan_adjustment_target_place_id`: place id targeted by the request

## Local Behavior Engine

The local no-network behavior-engine scaffold is configured with:

```yaml
behavior.engine: 'default'
behavior.llm.enabled: false
behavior.llm.deliberation_interval: 60
behavior.llm.max_memory_events: 20
behavior.llm.signal_cap: 1.5
behavior.llm.memory_decay: 0.65
behavior.activity_semantics.social_ids: []
behavior.activity_semantics.flexible_ids: []
behavior.activity_semantics.mandatory_ids: []
behavior.activity_semantics.travel_sensitive_ids: []
```

Key meanings:

- `behavior.engine`: choose `'default'` or `'llm_local'`
- `behavior.llm.enabled`: enable the local behavior scaffold without changing `behavior.engine`
- `behavior.llm.deliberation_interval`: coarse interval between deliberation passes when no salient trigger is present
- `behavior.llm.max_memory_events`: size of the short-term episodic-memory window exposed to the adapter
- `behavior.llm.signal_cap`: saturation cap for repeated appraisal signals
- `behavior.llm.memory_decay`: decay applied when appraisal traces are reused from memory on later ticks
- `behavior.activity_semantics.social_ids`: activity ids to treat as social
- `behavior.activity_semantics.flexible_ids`: activity ids to treat as flexible in addition to defaults
- `behavior.activity_semantics.mandatory_ids`: activity ids to treat as mandatory
- `behavior.activity_semantics.travel_sensitive_ids`: activity ids to treat as travel-sensitive in addition to defaults

Tuning guidance:

- lower deliberation interval: more reactive agents
- higher memory-event window: longer short-term carryover
- higher signal cap: stronger accumulation from repeated messages
- lower memory decay: faster fading of remembered signals
- semantics overrides are additive and preserve conservative defaults
- social behavior stays off by default until `behavior.activity_semantics.social_ids` is configured

Current constrained adjustment support:

- safety-driven `stay_home` can emit `preserve_home_activity`
- this preserves home by rewriting the remainder of the current day into a home activity
- coordination or travel-delay guidance can emit `defer_next_activity`
- this shifts only the next future activity later, bounded by available slack
- narrow cancel or skip-style coordination / recommendation messages can emit `skip_flexible_activity`
- this removes only the next future flexible activity from the active plan
- social-cancel messages can emit `cancel_social_activity`
- this removes only the next future social activity and requires a configured `behavior.activity_semantics.social_ids` override
- without a social override, non-social activities are left unchanged
- requested and applied adjustment state is exposed in the behavior log, including skip reasons and target activity metadata

Example scenario override:

```yaml
behavior.engine: 'llm_local'
behavior.activity_semantics.social_ids: [1]
```

With that override, a future activity with `activity_id = 1` is treated as social. A `coordination` message with topic `cancel_social` can then trigger `cancel_social_activity` and remove that next future social activity from the active plan. Without the override, the same message leaves the activity unchanged.
